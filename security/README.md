# AI위드스쿨 보안 정비

2026-10-03. GitHub Pages 공개 사이트와 AIWITH Supabase 프로젝트에 적용.

## 변경

- 브라우저 및 상담 API의 공용 비밀번호와 해시 검증을 폐기한다. 기존 등록된 카드뉴스 운영 계정만 private 관리자 레지스트리에 유지한다. 사용자 입력 metadata나 향후 신규 가입을 관리자로 인정하지 않는다.
- Supabase Auth의 getUser로 인증을 검증하고 서버 RPC/RLS로 권한을 확인한다. 공개 HTML/JS 자체를 비공개 서버 화면이라고 표현하지 않는다.
- 상담 조회는 검증된 사용자의 RLS 문맥을 사용한다. 일반 가입자는 상담·통계를 볼 수 없고 콘텐츠·파일을 변경할 수 없다. 고객 첨부 버킷은 비공개를 유지한다.
- 익명 상담 제출은 기존 공개 Edge Function으로 유지한다. 공개 테이블 직접 INSERT는 폐기하고 서버 검증, 허용 출처, 32KB 요청 상한, honeypot, 원자적인 시간당 60건 예산을 사용한다. 출처 확인은 관리자 인증의 대체가 아니다. 요청 예산은 공격자가 모두 사용할 수 있으므로 완전한 DDoS/봇 방지라고 표현하지 않는다.
- 2026-10-03 사용자 승인에 따라 Resend 알림을 구성한다. 승인된 수신 주소는 서버의 private.aiwith_notification_settings에 비공개로 저장하며 공개 저장소에 기록하지 않는다. 수신 설정은 서비스 역할만 조회할 수 있다. 제목 ‘새 상담 접수’와 관리자 링크 https://aiwith.kr/admin/만 전송한다. 메일 함수는 상담 데이터를 인자로 받지 않으며 이름·전화·이메일·기관·상담내용·첨부·접수 ID·접수 경로를 전송하지 않는다. RESEND_API_KEY와 RESEND_FROM은 기존 서버 비밀 설정만 사용한다. 상담 입력값을 새로 localStorage에 저장하지 않는다. 이전에 사용자가 저장한 상담 기록이나 초안을 자동 삭제하지 않는다.
- 관리자 세션은 탭 sessionStorage에 저장하며 무활동 30분 후 로그아웃한다. 현재 탭 세션만 종료하며 다른 기기 계정을 임의로 변경하지 않는다.
- 허용 스크립트 출처와 정적 인라인 스크립트 hash 기반 CSP, referrer 정책, 고정 Supabase JS 2.117.2를 적용한다. 향후 컬럼 생성/사이트 재빌드에서도 보안 정책을 재생성한다.

## 검증

`node --test scripts/notification.test.mjs scripts/security.test.mjs scripts/publish-columns.test.mjs`

`node scripts/check-security.mjs`

21개 자동 테스트 통과. 실제 DB 역할 전환 검사에서 일반 계정은 관리자 권한 false, 상담·통계 조회 0건이며, 기존 운영 계정은 관리자 권한 true로 확인했다. 익명 저장소 목록 조회는 0건이고 공개 카드뉴스 4개·카드 20개는 유지했다. 배포된 API에서 토큰 없는 조회와 위조 토큰은 401, 다른 출처는 403으로 확인했다. 고객 상담 입력이나 외부 메일 발송을 테스트에 사용하지 않았다.

백엔드 함수: security/consultation/index.ts 및 handler.mjs. 공개 제출 때문에 기존 verify_jwt=false를 유지하되, list 작업은 JWT Auth 검증 + 관리자 레지스트리 + RLS를 모두 통과해야 한다. 서비스 키는 Supabase 서버 환경에서만 읽으며 클라이언트나 저장소에 기록하지 않는다.

알림 추가 검증: 27개 자동 테스트 통과. 상담 데이터가 메일 인자로 전달되지 않고 Resend 본문은 비공개 서버 설정의 수신자·고정 제목·관리자 링크로만 구성되는 것을 확인한다. 키 누락·API 오류·시간 초과는 성공으로 기록하지 않으며 메일 실패와 무관하게 상담 저장은 유지한다. 실제 연동 점검에 사용한 ‘알림 연결 테스트’ 1건은 고객 상담이 아닌 가상 접수이며 임의로 삭제하지 않는다. 발송 수락과 실제 받은편지함 배달은 구분해 보고한다.

실제 검증 결과(2026-10-03): 가상 접수는 HTTP 200으로 저장됐지만 email_status=not_configured, email_sent=false였다. 서버 RESEND_API_KEY가 비어 있어 실제 외부 발송은 실행되지 않았다. 키 및 Resend의 허용된 발신자 설정을 등록한 뒤 재검증해야 하며 현재 알림이 발송된다고 보고하지 않는다.

## 운영상 남는 조치

- 기존 공용 비밀번호는 이 사이트에서 더 이상 유효하지 않다. 다른 계정에서 같은 비밀번호를 썼다면 해당 계정의 소유자가 변경해야 한다. GitHub 과거 이력은 임의로 삭제/강제 재작성하지 않는다.
- Supabase의 유출 비밀번호 차단, MFA, 가입 제한 설정은 계정 소유자가 dashboard에서 확인할 대상이다. 설정 완료를 검증하지 않았다면 완료라고 보고하지 않는다.
- GitHub Pages에서는 이 코드만으로 HSTS, X-Frame-Options, CSP frame-ancestors, Permissions-Policy 응답 헤더를 설정할 수 없다. meta CSP는 frame-ancestors를 지원하지 않는다. 관리자 UI는 iframe에서 인증하지 않지만 이는 서버 헤더를 대체하지 않는다. DNS/호스팅 변경이나 보호 프록시 도입은 별도 승인·구성이 필요하다.
- 고객 첨부와 문서 파일의 악성코드 검사, CAPTCHA는 별도 서비스 설정 없이 구현했다고 주장하지 않는다. 공개 강의 PDF·이미지 같은 정적 자산은 접근 URL이 알려지면 내려받을 수 있다.
- 실제 관리자 계정으로의 로그인 검증에는 소유자의 안전한 인증 입력이 필요하다. 소스에 노출된 비밀번호를 테스트 로그인에 재사용하지 않는다.
