# AI위드스쿨 멘토K 컬럼 발행 규약

대상 저장소: `mentor-k/chatgpt-sites-projectbook`, 브랜치 `main`, 공개 주소 `https://aiwith.kr/columns/`.
예약은 ChatGPT 자동화에서 실행한다. 웹페이지 방문, 브라우저 임시저장, 별도 AI API 키에 의존하지 않는다. 오전 8시는 작성 작업 시작 시각이며 공개는 작성·검수와 GitHub Pages 배포가 끝난 뒤다.

## 매 실행 절차

1. GitHub 연결 도구로 최신 main 및 `columns/topics.json`, `columns/posts.json`, 이 규약과 `scripts/publish-columns.mjs`를 읽는다. 과거 실행의 파일이나 SHA를 재사용하지 않는다.
2. 기존에 게시된 것으로 기록된 최신 글의 실제 공개 페이지와 배포 성공 여부부터 확인한다. 공개가 확인되지 않으면 이전 배포 문제를 보고하고 새 주제로 넘어가지 않는다. Asia/Seoul의 오늘 날짜로 게시된 글이 있으면 중복 게시하지 않는다. posts에 없는 가장 작은 주제 번호를 선택한다. 30편이 모두 게시되면 새 주제를 임의로 만들지 말고 완료를 보고하고 이 컬럼 자동화를 일시정지한다. 검수 보류일에는 다음 주제를 소진하지 않고 다음 실행에서 같은 주제를 다시 작성한다.
3. 제목·부제·2문장 검색/AI답변 요약·본문 1,800~2,300자·소제목 3개 내외·실행 제안·주제에 맞는 강의/워크숍 CTA·해시태그 6개를 작성한다. 김용한 박사(멘토K)의 전문적인 평서체 컬럼으로 작성한다. 고객에게 판매 문구를 반복하기보다 문제 해석과 실천 기준을 제공한다.
4. 개인 강의 경험·실적·고객 사례·매출·효과 수치를 지어내지 않는다. 예시는 가상이라고 표시한다. 최신 제품·정책·기능을 언급하면 공식 원문과 기준일을 확인한다. 확인 불가하면 해당 내용을 삭제하거나 게시를 보류한다. 검색순위·AI추천·교육성과를 보장하지 않는다. 저작권·개인정보·과장 광고를 검수한다.
   - 외부 컬럼·기사의 제목, 문장, 사례 배치, 핵심 비유, 소제목 순서를 따라 쓰거나 동의어만 바꿔 재작성하지 않는다. 사실 확인과 원고 창작을 분리하고, 원고는 교육 대상의 구체적 문제와 독자적인 실행 기준에서 작성한다.
   - 게시 후보 제목을 따옴표 검색하고, 특징적인 본문 문장 2개도 검색해 공개 글과 유사성을 점검한다. 제목이 흔한 표현이면 AI위드스쿨 교육 대상·구체적 산출물·관점이 드러나는 제목으로 조정한다. 검색에서 발견되지 않았다는 이유만으로 무중복을 보장하지 않는다.
   - AI위드스쿨의 이전 컬럼과 사용자 운영 사이트 minext.kr, mentork.kr, rndlab.kr, gongmolab.kr, localnext.net의 공개 제목·본문도 확인 가능한 범위에서 점검한다. 주제가 같더라도 문장을 재사용하지 않고 본 사이트의 교육·워크숍 관점으로 차별화한다.
   - 외부 원문 인용은 가급적 피하며 불가피한 짧은 인용은 인용부호와 실제 원문 출처를 연결한다. 출처를 달아도 장문 전재는 하지 않는다. 특징적 표현·핵심 전개가 유사하면 처음부터 다시 작성한다. 유사성을 해소하지 못하면 게시를 보류한다.
   - 글마다 originality={checkedAt,queries:[실제 실행한 검색어],note} 검수 기록을 넣는다. 확인하지 않은 검색을 기록하거나 법적 안전을 보장했다고 표시하지 않는다.
5. CTA는 해당 교육의 대상·실습 산출물을 구체적으로 제안하고 `/consultation/`, `/workshops/`, 전화 `010-3338-7110`을 연결한다. 등록하지 않은 전화·실적·기관명은 만들지 않는다.
6. 아래 스키마로 posts에 글 1개만 추가한다. 기존 글은 수정하거나 삭제하지 않는다. 초안이나 검수 미통과 글을 공개 posts에 넣지 않는다.
7. 최신 저장소를 작업공간에 읽어 `node scripts/publish-columns.mjs --check`, `node scripts/publish-columns.mjs`를 실행한다. 목록·상세 HTML·sitemap·컬럼 RSS·발행계획을 생성한다. 스크립트가 없거나 실행 불가면 임의로 동적 화면만 만들지 말고 중단한다.
8. GitHub 연결 도구의 blob/tree/commit/ref로 변경 파일만 한 커밋에 저장한다. 최신 main을 부모로 삼고 force=false로 갱신한다. 경합하면 최신 main을 다시 읽고 중복 여부를 재확인한다. 인증·보호 워크플로가 막히면 우회하지 않는다. 기존 관리자 인증 파일은 수정·재업로드하지 않으며, 저장소의 인증정보를 추출하거나 로그인에 사용하지 않는다.
9. 저장본을 재조회하고 GitHub Pages 배포 및 공개 목록·상세·CTA를 확인한다. 실패 시 다음 글로 넘어가지 않는다. 결과에 주제 번호·제목·실제 URL·검증 결과·남은 편수를 보고한다.

## 게시 글 스키마

`posts.json`의 posts 배열: `topicId`(1~30), `slug`(topics와 동일), `status`="published", `title`, `subtitle`, `summary`, `sections`=[{heading, paragraphs:[문단 문자열]}], `takeaway`(선택), `cta`={text}, `hashtags`=[6개], `sources`=[{label,url}](원문을 참고했다면 실제 출처), `originality`={checkedAt,queries:[검색어 3개 이상],note}, `publishedAt`(실제 게시 ISO 시각), `updatedAt`(동일 시각).

본문 글자수는 sections의 문단을 합친 값으로 계산한다. HTML을 입력하지 않는다. 본문을 안전하게 escape해 서버 생성 HTML에 렌더링한다. 미래 시각·중복 주제·중복 날짜는 검증에서 거부한다. 이미지가 필요하면 승인된 기존 자산이나 생성 도구를 사용하고 실제 현장사진으로 오인시키지 않는다. 이미지는 필수 요건이 아니며 임의의 외부 이미지를 가져오지 않는다.

## 수동 글쓰기와 구분

`/admin/#writing`은 기존 관리자 인증을 유지한다. 수동 초안은 브라우저 로컬 저장 기능이며 중앙 공개 게시는 아니다. 이 초안을 예약 작업이 읽는다고 주장하지 않는다. 자동 발행은 GitHub의 공개 원고 데이터와 생성 HTML을 사용한다.
